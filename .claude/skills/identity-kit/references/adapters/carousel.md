# Adapter - carousel

Template (add-on). Fill every `{{...}}` from kit.json. Recycled from brand-studio's make-branded-carousel logic (lock one system from tokens, repeat it verbatim per slide) and the Tuesday carousel prompt as the worked example of precision.

## Purpose and when to attach
Multi-slide posts (Instagram, LinkedIn) where 3-8 images must read as one set. Attach with `core.md` and `image-style-block.md` when the request is "make a carousel ...". Single posts use `adapters/social-post.md`.

## Format specs
- 1080x1080 (1:1) or 1080x1350 (4:5); the same size for every slide in the set. 3-8 slides.
- Headline floor {{typography.floors.post_headline}}px, sub-line about one quarter of the headline size and never below 32px.
- Slide 1 is the hook, the last slide is the call to action. Middle slides carry one idea each.
- Export PNG, numbered `assets/carousel-<topic>-01.png` ... in order.

## Core in this medium
- Colors: one canvas for the whole set ({{color.bg}} or {{color.accent_strong}}); one accent {{color.accent}}; at most one secondary accent. No color that appears on one slide only.
- Type: heading family, one weight, one alignment ({{composition.alignment}}) for all slides. Sub-line in body family.
- Tokens: if a card is used, same radius {{tokens.radius.lg}}px and the Core shadow on every slide.
- Motifs: exactly one motif, same position and size on every slide (a corner anchor or a bottom rail). Never a different motif per slide.
- Logo: same corner, same size, every slide ({{logo.placement.post}}).
- Imagery: either no imagery, or one image per slide in the same crop and treatment (Core 6/7); never mixed.

## Layouts
1. **Text set** - canvas, headline top-center, sub-line below, motif bottom-corner, logo opposite corner. Text is the only thing that changes.
2. **Card set** - a surface card holds headline + sub-line; the canvas around it shows the motif rail; slide number as a small chip.
3. **Image set** - image top half in the locked treatment, solid band bottom half with headline; motif on the band only.

## Rules and gotchas
- Lock the visual system once, write it down as a block, and repeat it word for word in every slide prompt or slide file. Vary content, never system.
- If any slide drifts (font size, color, motif position), regenerate that slide only.
- Text on generated images is unreliable in Hebrew; when the set is generated by an image model, generate text-free slides and overlay text in HTML or a design tool. When built as HTML, text is native.
- Consistency check before finishing: same background hex, same accent hex, same font, same headline size, same motif position, same logo position on all slides.

## Drop from Core here
- Secondary accents beyond one, multiple motifs, print and email rules.

## Usage prompt (copy-paste, attach with core.md and image-style-block.md)
```text
Read core.md, adapters/carousel.md and image-style-block.md. Build a <N>-slide <1:1 | 4:5> carousel about: <topic>. Slide texts: <list, or write them: hook, one idea per middle slide, CTA last>. Use layout <1 Text set | 2 Card set | 3 Image set>. First write the locked visual system as one block (canvas hex, accent hex, font and sizes, motif and its position, logo position). Then produce every slide as a self-contained HTML file sized to the format, or, if I ask for image prompts, one prompt per slide that repeats the locked block verbatim and changes only the text. Finish with the consistency check and the Core gate.
```

## Done-check
1. Every slide is the same size, canvas hex and accent hex.
2. Same font, headline size and alignment on all slides.
3. One motif, same position and size everywhere.
4. Logo same corner and size on every slide.
5. Slide 1 hooks, last slide calls to action, middle slides one idea each.
6. Files numbered in order under assets/.
